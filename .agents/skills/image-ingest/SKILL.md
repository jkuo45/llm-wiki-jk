# Image Ingest (local ollama OCR)

Turn an image located in `raw/` (or elsewhere) into a curated note entry in the
Notes panel (`src/images/`), transcribing its text with a **local ollama vision
model** — no cloud/API OCR.

## When to use

- A screenshot (e.g. graph-analysis UI, prompt, results, node sets) or photo of
  handwritten notes needs to be added to the wiki's Notes panel.
- A figure from a paper needs to be captured as a note so pages can reference it
  (see "Referencing a note image from a page").
- The source image lives in `raw/` (or a given path) and should be moved into a
  per-note folder in `src/images/`.
- You need an `ocr` transcription for the manifest entry.

## Conventions (follow exactly)

- **One image per folder.** Each note folder holds exactly one image file (its
  original basename). Two separate screenshots → two separate folders + two manifest entries.
- **Folder naming**: `src/images/n-<YYYYMMDD>-<slug>-00/`
  - `YYYYMMDD` = today (e.g. `20260915`)
  - `slug` = short kebab-case descriptor (e.g. `sasp-regulation-scheme`)
  - `-00` suffix (collision counter if needed)
- **Retain the original file name** — do NOT rename to `page-N`. When copying
  into the note folder, keep the source basename (e.g. `IMG_6170.jpeg`,
  `gr1_autophagosomes.jpg`, `cellular_senescence_1565f02.jpg`). The manifest
  `pages[].file` must list that basename. (Preserves source provenance and
  avoids ambiguity across notes.)
- **Move, don't copy**: after copying the image into its note folder, remove the
  original from `raw/` (the user's "move image there" intent).
- Timestamps: the manifest stores `created`/`updated` as frontmatter-style
  `YYYY-MM-DD`. The runtime (`api/routers/notes.py`) reads only these — it does
  **not** store `created_at`/`updated_at` (older notes may still carry a stale
  `updated_at`, which is just a leftover and can be dropped).

**Notes data layout** (`src/images/`):
- `manifest.json` — committed, curated notes (the durable source of truth that
  ships with the wiki); the runtime serves it read-only and never writes it.
- `.staged.json` — legacy; previously held live browser uploads, but live
  uploads were removed. It is empty and no longer written; leave it alone.
- `n-<date>-<slug>/` — per-note folders holding image files and optional
  `.thumb` siblings. (There is no `<topic>/` parent directory; the slug inside
  the note id carries the topic.)
- **In-place notes** — a note may carry an optional `path` (see schema) pointing
  at an original image that stays elsewhere in the repo (resolved relative to
  `src/images/`); its thumbnail lives in `src/images/<id>/` and the source is
  never moved. Most notes omit `path`.

> [!note] Two different `manifest.json` files
> `src/images/manifest.json` (above) is the **Notes-panel** manifest served via
> `api/routers/notes.py`. It is unrelated to `web/public/data/manifest.json`, the **graphify
> content manifest** generated by `scripts/triples/rebuild.py` — a
> hash map of `src/notes/**`, `_triples.json`, and `tasks/**` source files
> (`{mtime, ast_hash, semantic_hash}`). That file is a graph build artifact, not
> a notes schema; never treat it as one.

## Tooling and authoritative data files

Read these instead of relying on memorized lists — they are generated or
hand-maintained, and any hard-coded copy in documentation drifts.

| Source | What it gives you |
|---|---|
| `web/public/data/topics.json` | The valid **TOPIC** slugs. Generated by `scripts/triples/rebuild.py` (`write_topics_json`) from the `src/notes/*/` directory layout — underscores → hyphens, `_link/` excluded. Add a topic by creating a `src/notes/<topic>/` dir, then re-run the rebuild. |
| `web/public/data/notes-tags-zh-TW.json` | The **tag vocabulary** (its keys are every valid tag slug) plus the 繁體中文 labels the Notes panel renders. |
| `web/public/data/nodes.json` | Canonical **entity labels** for `entities[]` — the combined (triples ∪ wiki) dataset, and the widest label set. Prefer it over `graphify-out/graph.json`, which lacks many wiki-only labels (e.g. `IRF3`, `CEBPβ`, `MAPKAPK2`). |

Only two scripts under `scripts/` are maintained for the notes manifest:

```bash
# Reorder tags (TOPIC first, FORMAT next, then content ranked by entity match). Idempotent.
uv run python scripts/tools/sort_manifest_tags.py

# Backfill <stem>.thumb.<ext> for any note page missing one. Idempotent.
uv run --with pillow python -m scripts.tools.thumbnail
```

Older revisions of this skill referenced a vocabulary normalizer, a
markdown/transcript tightener, and a qwen re-OCR applier. Those scripts no longer
exist — see "Retired tooling" at the end before running anything you find under
`.tmp/`.

## Workflow

### 1. Read the image context

Look at the image and note what it is (diagram, screenshot, handwriting), its
approximate structure, and — for a paper figure — whether the caption or the
filename identifies the source. That determines the `title`, `tags`, and
`entities` you will write.

### 2. Pick a vision-capable ollama model

```bash
ollama list
```

Pick a **vision-capable** (multimodal) model. If none is available, tell the
user and stop rather than fabricating OCR.

Observed behaviour worth knowing: `gemma3` is fast but on a dense multi-label
pathway diagram it returned roughly two thirds of the labels and missed whole
clusters; `qwen3.5` returned noticeably better coverage and grouping on the same
image. For a **dense scientific figure**, run two models and merge — the union is
more complete than either alone — then correct against the image. For plain
handwriting, one model is usually enough.

### 3. OCR each image

Create the note folder and copy the image in first (OCR works off the final
path, and the manifest points into the folder):

```bash
mkdir -p "src/images/n-20260915-<slug>-00"
cp raw/<source>.<ext> "src/images/n-20260915-<slug>-00/<source>.<ext>"
```

Then run ollama on the copy. Clean the ANSI control-char noise from the output:

```bash
OLLAMA_NOPROGRESS=1 ollama run <model> \
  "Transcribe ALL visible text in the image at the absolute path: <ABS_PATH_TO_PAGE>. Output ONLY the transcribed text, faithfully, in simple plain text. Use plain formatting only: no markdown, no bold or asterisks, no # headings, no table pipes. Do NOT add any meta or framing phrases such as 'Here's the transcription:', 'The image shows', or 'OCR result:', and no preamble or summary. If there are diagrams/arrows, describe them briefly in plain text." \
  2>/dev/null | sed 's/\x1b\[[0-9;?]*[a-zA-Z]//g' | tr -d '\r'
```

For a reasoning model such as `qwen3.5`, add `--think=false` — otherwise it can
loop for many minutes on a dense figure.

**Prompt guidance**
- Reference the image **by absolute path** — that is how ollama attaches it.
- Ask it to preserve structure (headings, lists, bullets) and fold diagrams /
  buttons into brief inline notes so nothing meaningful is lost.
- Run OCR **per image** (one call each).
- **Keep the model's output clean** — ask for simple plain-text formatting and
  no meta-framing (no `"Here's the transcription:"`, `"The image shows"`,
  `"OCR result:"`, or summaries). If any such phrase slips through, strip it in
  post-processing so the `ocr` field begins directly with the content.
- **Post-process the output**: strip ANSI escapes (shown above), remove UI
  spinner/toolbar noise, fix obvious OCR errors, and normalize symbols to
  standard forms (e.g. `NAD+`, `SIRT1`, `IL-1β`). Cross-check every label
  against the image; OCR models silently drop and invent short tokens.
- For a paper figure, it is legitimate to **complete the transcription from the
  image yourself** — you can see it. Say so implicitly by keeping the `ocr` text
  faithful to what the figure actually shows; do not pad it with the model's
  guesswork.
- **Store plain text only** — `translations[locale].title`/`ocr` are plain-text
  fields, not markdown. Normalize to the project's plain-text standard before
  writing it (see "OCR plain-text hygiene").

### 4. Add the manifest entry

Append a new object to `src/images/manifest.json` (keep existing entries). Write
it with a small script rather than hand-editing, so the JSON stays valid:

```bash
python3 - <<'PY'
import json, collections
p = "src/images/manifest.json"
m = json.load(open(p, encoding="utf-8"))
e = collections.OrderedDict()
e["id"] = "n-20260915-<slug>-00"
e["document"] = ""
e["entities"] = [...]          # canonical labels from web/public/data/nodes.json
e["tags"] = [...]              # topic first; every slug present in notes-tags-zh-TW.json
e["pages"] = [{"page": 1, "file": "<source>.<ext>"}]
e["annotations"] = []
e["created"] = "2026-09-15"; e["updated"] = "2026-09-15"
e["author"] = "you"
e["draft"] = False
e["translations"] = {"en-US": {"title": "...", "ocr": "..."},
                     "zh-TW": {"title": "...", "ocr": "..."}}
m.append(e)
json.dump(m, open(p, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
PY
```

**Record schema** (this is the single source of truth for the manifest entry):

```jsonc
{
  "id": "n-20260915-sasp-regulation-scheme-00",
  "document": "_document_ - sirtuins ... .md",   // plain filename; no wiki links in data files
  "entities": ["SASP", "NF-kappaB", "IRF3"],    // concepts = graph node labels (plain text)
  "tags": ["senescence", "diagrams-charts", "sasp"],  // topic first, then FORMAT/CONTENT
  "pages": [{ "page": 1, "file": "cellular_senescence_1565f02.jpg" }],
  "translations": {
    "en-US": { "title": "...", "ocr": "..." },  // default locale; title + ocr always live here
    "zh-TW": { "title": "...", "ocr": "..." }   // optional bilingual pair
  },
  "annotations": [{ "id": "a1", "type": "circle", "page": 1,
                    "x": 0.3, "y": 0.4, "r": 0.08, "color": "#ffcc00", "label": "" }],
  "path": "../<topic>/<file>",   // optional; in-place source, anchored at src/images/
  "created": "2026-09-15", "updated": "2026-09-15",
  "author": "you",
  "draft": false
}
```

`translations` is the single home for all localizable content: `title` and `ocr`
for every locale. **`en-US` is the canonical default** — every entry must carry
it, and readers fall back to it (there is no top-level `title`/`ocr`/`ocr_lang`
anymore; those only remain on legacy/un-migrated entries and are used as
fallbacks).

Annotation coordinates are normalized 0–1 across tools:
- `circle` → `x, y, r`
- `rect` → `x, y, w, h`
- `arrow` → `x1, y1, x2, y2`
- `label` → `x, y, label`

**Field decisions**
- `entities`: the **concepts** the note is about, written as canonical graph
  labels. Look them up against the combined dataset and keep the exact label
  string (the graph is keyed by `norm(label)`, so `NF-kappaB` — not `NF-κB` —
  and `Notch` — not `NOTCH1`):

  ```bash
  python3 - <<'PY'
  import json
  labels = {(n.get("label") or n["id"]) for n in json.load(open("web/public/data/nodes.json"))}
  for c in ["SASP", "Cellular Senescence", "NF-kappaB", "IRF3", "Notch", "TLR2/6"]:
      print(c, c in labels)
  PY
  ```

  Where the figure names a specific isoform that has no node (`NOTCH1`, `RIG-I`,
  `IL-6R`, `PTBP1`), list the plain-text name — never a `[[wiki link]]` — and
  expect it to be flagged for entity-note creation. Include both when useful
  (`Notch` for graph linkage, plus the exact `NOTCH1` from the figure).
- `tags`: a small **facet** vocabulary, capped at ≤12, never invented. The
  **first tag is exactly one TOPIC slug** from `web/public/data/topics.json`;
  the rest are FORMAT then CONTENT facets. Every slug must be a key in
  `web/public/data/notes-tags-zh-TW.json`:

  ```bash
  python3 - <<'PY'
  import json
  vocab = set(json.load(open("web/public/data/notes-tags-zh-TW.json")))
  tags = ["senescence", "diagrams-charts", "sasp", "inflammation", "nf-kappab"]
  print("unknown:", [t for t in tags if t not in vocab])
  PY
  ```

  - **TOPIC** (exactly one, first) — read `web/public/data/topics.json`; do not
    hard-code the list here. Currently: `adrenochrome`, `autophagy`, `cancer`,
    `cell-death`, `comt`, `epigenetics`, `hormesis`, `neuromelanin`,
    `oxidative-stress`, `senescence`, `sirtuins`.
  - **FORMAT** — `diagrams-charts`, `graph-analysis`, `generated-image`, and
    `notes` (**handwritten only**).
  - **CONTENT** — mechanistic/physiological facets derived from the entities and
    OCR (e.g. `sasp`, `inflammation`, `nf-kappab`, `innate-immunity`,
    `nad-metabolism`, `redox`, `senolytics`, `mitochondria`). The vocabulary is
    large (~560 slugs) and does include some concept-named slugs for filtering —
    that is not licence to add new concept tags: **concepts belong in
    `entities`**, and a tag may only coincide with an entity when it is the
    TOPIC slug.
  - **Banned legacy tags** — `photo`, `paper-figure`, `bilingual`, `speculative`,
    `comparison`, `misc`. Never add them. Their intended replacements are
    `diagrams-charts` (for a printed figure or infographic), and plain
    `entities`/`tags` entries otherwise. There is currently **no automated
    normalizer** that strips them (see "Retired tooling") — fix any you find by
    hand.
  - **`notes` = handwritten only.** A photo of a printed infographic / paper
    figure is NOT `notes` — tag it `diagrams-charts` instead. A note never
    carries both `notes` and `diagrams-charts`.
- `tags` ordering: after writing the entry, run
  `uv run python scripts/tools/sort_manifest_tags.py`. It keeps the TOPIC first,
  pulls FORMAT tags forward, and ranks CONTENT tags by whether they match an
  entity. It is idempotent, so it is safe to re-run.
- `topic` is not a stored field — it lives as the first `tags` entry.
- `translations[locale].ocr`: single page → just the text. Multi-page (separate
  entries) each carry their own page text. English goes in
  `translations["en-US"]` (the always-present default); translations in their
  locale key. For a paper figure, finish the transcription with the figure's own
  caption and the source citation on their own lines — that is what makes the
  entry findable later:

  ```
  ...transcribed labels and structure...
  Figure caption: <the caption, verbatim if known>
  Source: <Authors. Title. Journal. Year;volume(issue):pages. doi:...> Figure N.
  ```
- `pages[].file`: the **original source basename** (not `page-1`), e.g.
  `cellular_senescence_1565f02.jpg`. It must exactly match the file placed in
  the note folder.
- `document`: filename of the related `_document_ - …md` note in `src/notes/`,
  if one exists; otherwise `""`. Do not invent one.
- `path` (optional): in-place source anchored at `src/images/`; the API resolves
  it safely and serves its thumbnail from `src/images/<id>/`. Omit it for the
  usual notes whose images already live inside the note folder.
- `created`/`updated`: frontmatter-style `YYYY-MM-DD` dates. Do **not** add
  `created_at`/`updated_at` ISO timestamps — the runtime does not store them.
- `draft`: `false` once the entry is complete; `true` only for a deliberately
  unfinished placeholder. Most ingests are `false`.
- When a value is genuinely unknown/not applicable, leave `document` as `""` and
  `annotations` as `[]` rather than inventing data.

Validate the file and confirm the entry landed:

```bash
python3 -m json.tool src/images/manifest.json > /dev/null && echo "JSON OK"
python3 -c "
import json
m = json.load(open('src/images/manifest.json'))
e = [x for x in m if x['id'] == 'n-20260915-<slug>-00'][0]
print(len(m), 'entries;', e['tags']); print('ocr chars:', len(e['translations']['en-US']['ocr']))
"
```

### 4b. Generate a thumbnail

Every note needs a `<stem>.thumb.<ext>` sibling: the web gallery requests
`?thumb=1` for every card / page-strip, and the API serves the full-resolution
original when no thumbnail exists (making the gallery slow). Once the manifest
entry is in place, run the shared backfill script — it scans `src/images/`
(manifest + staged) and creates a `.thumb` for any page that lacks one
(idempotent, format-preserving, keeps EXIF orientation):

```bash
uv run --with pillow python -m scripts.tools.thumbnail
```

Confirm this note's thumbnail was written:

```bash
ls -lh src/images/n-<YYYYMMDD>-<slug>-00/
# expect: <source>.<ext>  AND  <source>.thumb.<ext>
```

### 5. Clean up `raw/`

Remove the original from `raw/` now that a copy lives in the note folder:

```bash
rm raw/<source>.<ext>
```

## Rules / pitfalls

- **One folder per image** — never lump two screenshots into one folder as two
  page files unless the user explicitly wants a multi-page note.
- **Retain original file names** — do not normalize to `page-N`; keep the source
  basename in the folder and in `pages[].file`.
- **No wiki links in data files** — `translations[locale].ocr`,
  `translations[locale].title`, `entities`, `document` are plain text, never
  `[[...]]`.
- **Never invent a tag slug.** Check membership in
  `web/public/data/notes-tags-zh-TW.json` first; if the facet genuinely does not
  exist, add it to that file (with a 繁體中文 label) *and* use it — do not add a
  one-off slug to the manifest alone.
- **OCR plain-text hygiene** — the manifest `ocr`/`title` fields are **plain
  text, never markdown**. Normalize the transcription to the cleaned-vault
  standard (no bulk helper currently exists, so apply by hand):
  - **Markdown formatting**: remove bold `**...**`, italic `*...*`, code
    backticks, `#` headings, `> ` blockquotes, and `---` horizontal rules.
    Keep genuine significance stars (`**** (p<0.01)`, `*** (p<0.001)`).
  - **Line breaks**: collapse runs of 2+ newlines to a single `\n` (no blank
    lines / paragraph breaks).
  - **OCR/HTML sentinels**: remove stray `*` markers, `<start_of_image>` and
    `<end_of_image>` tokens.
  - **Tables**: remove table pipe `|` characters (cells merge, then collapse
    spaces) — `| A | B |` → `A B`.
  - **Bullets**: convert bullet glyphs (`•`, `●`, `◦`, `▪`, `‣`, `⁃`) to `- `.
    Leave the middle dot `·` only when it is a CJK/chemical separator.
  - **Whitespace**: trim leading/trailing spaces on every line and collapse
    internal runs to single spaces.
  - **Keep meaningful content**: leave OCR `[illegible]` flags and `->` arrows
    in place.
- **No fabricated OCR** — if a model cannot read the image (no vision), say so
  and stop; do not invent a transcription. Correcting a model's output from the
  image you can see is fine; inventing text that is not in the image is not.
- **Always strip ANSI / control characters** from `ollama run` output before
  storing it in the manifest.
- **Always generate the thumbnail** — after appending the manifest entry, run
  `uv run --with pillow python -m scripts.tools.thumbnail` (Step 4b) so the web
  gallery's `?thumb=1` requests get a small file instead of the full-resolution
  original.
- **Only touch `manifest.json`** — `.staged.json` is the legacy live-upload
  store and is no longer written (uploads were removed); leave it alone unless
  the user asks to reconcile.
- Timestamps must be real and plausible; match the project display-format rules
  in AGENTS.md where applicable.
- **Editing an existing entry**: reads/writes go through the same schema; write
  the whole list back with `json.dump(..., ensure_ascii=False, indent=2)` and
  keep the diff limited to the entry you touched. Never reformat the file.

## Re-OCR for garbled transcripts

Transcripts can drift from the page — OCR models garble handwriting, merge
labels, and append editorial narration ("The image contains…"). There is no
batch tooling for this anymore; handle it as a targeted manual fix:

1. Re-run the model on the **absolute path** of the source image, with thinking
   disabled for reasoning models:

   ```bash
   OLLAMA_NOPROGRESS=1 ollama run qwen3.5 --think=false \
     "Transcribe all visible text in the image at the absolute path: <ABS_PATH>. Output ONLY the transcribed text, faithfully, in plain text. No markdown, no headings, no meta framing, no summary." \
     2>/dev/null | sed 's/\x1b\[[0-9;?]*[a-zA-Z]//g' | tr -d '\r'
   ```

2. For handwriting, also try a second model and take the agreement — neither
   model is reliable alone, and a garbled transcript that looks fluent is the
   main failure mode.
3. Apply the plain-text hygiene rules above, then write just that entry's
   `translations[locale].ocr` back with a script that preserves the rest of the
   file byte-for-byte (same `json.dump` settings; check `git diff --stat` shows
   only your entry).
4. Never empty a transcript as a "cleanup" — a garbled transcript still beats
   none. If a page is genuinely unreadable, record what is legible and note the
   limitation.

## Bilingual tag labels (web)

The Notes web panel renders tags in the panel language. English uses the raw
slug; 繁體中文 pulls a label from `web/public/data/notes-tags-zh-TW.json`
(`{ <slug>: '繁體中文 label' }`) via `tagLabel()` in `web/components/notes.js`.

That file is hand-maintained and is the **vocabulary source of truth**: its keys
are every valid tag. Adding a tag means adding the slug to both the manifest
entry and this file (with a zh label) — otherwise the panel renders the raw slug
for 中文 readers. The topic taxonomy is separate and generated:
`web/components/notes.js` loads the valid topic slugs from
`web/public/data/topics.json`, which `scripts/triples/rebuild.py`
(`write_topics_json`) derives from `src/notes/*/`. The slug stays the source of
truth for filtering/search; only the displayed text is localized.

## Referencing a note image from a page

A page outside the Notes panel (e.g. an interactive explainer under
`web/public/pages/`) cannot reference `src/images/…` directly — that directory is
not part of `web/public/`, so it is not deployed with the site. Use the same URL
the Notes panel uses:

```
https://raw.githubusercontent.com/jkuo45/llm-wiki-jk/dev/src/images/<id>/<file>
```

(the base is `VITE_GITHUB_NOTES_IMAGE_BASE`, default as above; branch from
`GITHUB_BRANCH` in `.env`, currently `dev`).

- Link the image to the same URL so it opens full-resolution.
- Put the **source citation and the note id in a `<figcaption>`** so the figure's
  provenance travels with the page, and delete any duplicate copy you made under
  `web/public/` — the ingested note is the single source of truth.
- **Caveat**: the Notes panel falls back to `/v1/notes/image/…` via `onerror`
  when the raw URL is unavailable, but a static page has no such fallback. The
  figure therefore does not render until the entry is committed and pushed to
  the branch above (plus ~5 min of raw-cache lag). If the page must render
  offline, keep a local copy under `web/public/` as an `onerror` fallback
  instead — and say so in the caption.

## Optional: verify in the web app

If the server is running, the Notes panel at `web/index.html` surfaces these
entries. Confirm the new note appears and its image/OCR render correctly.

**Notes API** (`api/routers/notes.py`):

| Endpoint | Purpose |
|---|---|
| `GET /v1/notes` | Merged gallery index + `src/notes` document index |
| `GET /v1/notes/image/{id}/{page}?thumb=1` | Note photo (or thumbnail) |
| `POST /v1/notes/{id}/annotations` | Persist annotation overlays |
| `POST /v1/notes/{id}/metadata` | Update title / document / entities / tags |

Live browser uploads (`POST /v1/notes/upload`) and server-side OCR
(`POST /v1/notes/transcribe`) were removed; ingest is offline-only via this
skill. Note edits require super-admin auth; reads are public.
